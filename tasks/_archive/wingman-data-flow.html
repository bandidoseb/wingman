Wingman — Live Call Data Flow

What actually happens from "Deploy" click to signal card on screen

Phase 1 — Deploy
Rep clicks "Deploy Wingman"
Tray popover button. Triggers the entire pipeline.
electron/tray-popover/index.html
↓
IPC: call:start
Electron Main Process
Sets callActive = true · Guards against double-click with isStarting flag · Notifies HUD window
electron/main.ts
↓
calls initRecallAI()
Fetch Upload Token
Electron calls Railway API — Recall API key never leaves the server. Returns a short-lived token.
api/wingman/recall-upload-token
→ POST /api/wingman/recall-upload-token
← token (short-lived, scoped)
Session Created in DB
Loads Offer Brain + Flight Plan snapshot. Stores call record. Returns callId used for everything downstream.
api/wingman/session
→ POST /api/wingman/session
← callId, offerBrain, flightPlan
↓
sdk.startRecording() — confirms success before isRunning = true
Recall.ai SDK joins the meeting
Attaches to the active Zoom / Teams / Google Meet window. Begins capturing audio. Deepgram streaming transcription runs inside Recall's infrastructure — Wingman never touches raw audio.
electron/recall.ts
Phase 2 — Live Transcript Stream
Realtime Transcript Events
Recall fires transcript.data events as Deepgram transcribes. Each event has speaker label + text. Same utterance fires multiple times as words are finalized.
evt.event = "transcript.data"
evt.data.words[].speaker = "0" or "1"
evt.data.words[].text = transcript text
↓
per-speaker dedup (last-text comparison — drops repeats)
IPC → Web App Renderer
Clean, deduped chunk sent from Electron main process to the Next.js web app running in the renderer window. Format: "Speaker 0: [text]"
electron/main.ts → preload.ts → useWingmanPoller.ts
↓
addChunk() — two things happen simultaneously
Phase 3 — Two Parallel Paths (every chunk)
⚡ Path A — Instant Keyword Check
Keyword Trigger Classifier
Pattern-matches chunk against objection phrases. Runs in <1ms — no API call. Rep's own lines are excluded.
lib/wingman/keyword-triggers.ts
checks: price, think about it,
talk to spouse, not right time…
returns: signal card or null
↓
if hit → fireSignal() instantly
+ triggers Path B in parallel
Keyword Card — Instant <1ms
Fires immediately to HUD. Bypasses 90-second cooldown. Pre-written response for the detected objection.
🧠 Path B — RAG Pipeline (on keyword hit)
KB Signal Route
POST to Railway. Embeds the trigger chunk via OpenAI, searches pgvector for matching sales techniques.
api/wingman/kb-signal
→ chunk, callId, stage
← signal_header, signal_text
↓
OpenAI embed (~200ms) + pgvector search
Knowledge Base Search
Cosine similarity search against kb_prospect_triggers table (6,554 rows, HNSW index). Returns top 3 matching techniques with exact scripts + why it works.
lib/wingman/knowledge-search.ts
threshold: 0.65
returns: situation, exact_script,
why_it_works, call_stage
↓
~1,300 token prompt assembled
Claude Haiku ~480ms
System prompt + Offer Brain + KB techniques + trigger chunk → 5-word headline + 1-sentence subtext. Prompt caching on system prompt (saves 90% on repeat calls).
lib/wingman/knowledge-signal.ts
returns JSON:
{ headline, subtext, source }
Phase 3C — Poll Timer (parallel, every 8–90 seconds by stage)
Auto-Poll Timer → Claude Sonnet
Fires on a stage-based interval (fast in Discovery/Close, slow in Rapport). Sends the accumulated transcript buffer. Tracks call stage, updates live scorecard. Does NOT generate signal cards — that's Haiku's job.
api/wingman/poll → lib/wingman/system-prompt.ts
→ transcript_chunk, callId, current_stage
← stage, scorecard updates (via Pusher)
Phase 4 — Signal Delivery to HUD
Pusher WebSocket Push
Both kb-signal and poll routes push results via Pusher instead of making the client poll. Signal arrives the instant it's ready — not on the next poll interval. Channel is private, authenticated per user.
src/lib/pusher.ts → api/pusher/auth
channel: private-wingman-{callId}
events: wingman-signal, wingman-update
↓
useWingmanPoller Pusher subscription → IPC → hud:signal
HUD Signal Card Appears bottom-left overlay
Floating window on top of all apps. Invisible to prospect (screen share protected). Fades in, displays for ~8 seconds, fades out. 90-second cooldown before next card can fire. One card at a time — never queued.
electron/hud/index.html
Phase 5 — Call End
Call Stops
Rep clicks End, or auto-stop triggers (20-min inactivity or 2-hr max). stopRecallAI() is the single function that stops everything — clears timers, removes listeners, calls sdk.stopRecording().
electron/recall.ts → stopRecallAI()
"How'd it go?" HUD Card
Outcome picker fires on HUD. Rep selects: Closed / Lost / DQ / No Show / Follow-up. Saved via Bearer token — no login required at this moment.
api/wingman/outcome
↓
async — does not block HUD or rep
Phase 6 — Post-Call Job (async, Railway)
Claude Sonnet — Post-Call Analysis async
Runs against full transcript. Never runs during a live call. Produces: call grade, debrief summary, one win + one fix, objections detected, framework pillar coverage (7 pillars), Offer Brain delta.
api/wingman/post-call
↓
Flight Log Entry
Transcript, debrief, grade, pillar scorecard. Visible in dashboard immediately.
calls table (Supabase)
Offer Brain Update
JSON updated silently. Objection patterns, close timing, prospect archetypes refined. Never shown to rep.
offers table (Supabase)
Objection Vault
Objections from this call added to vault. Only populated from real calls — never seeded.
vault_objections table
