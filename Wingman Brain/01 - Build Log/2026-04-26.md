# Build Log — 2026-04-26

## Session: Pusher WebSocket Push Migration (#0b)

### What Was Completed

**Background KB scan removed (quick win #0a)**
- Removed the every-10-second background Haiku KB scan from `useWingmanPoller.ts`
- Previously: KB search ran on a timer regardless of call activity → $0.41/call wasted
- Now: KB search only runs when a keyword trigger fires
- Files changed: `src/hooks/useWingmanPoller.ts` (removed `lastKBCheckRef`, `KB_CHECK_COOLDOWN_MS`, `backgroundDue` variable, `else if (backgroundDue)` block)

**Full Pusher WebSocket push migration (#0b)**

Replaced polling-based signal card delivery with server-push via Pusher Channels. The poll route still runs on a timer to send transcript to Claude, but the resulting signal cards and scorecard updates now arrive via WebSocket instantly instead of waiting for the next poll cycle.

Cost reduction: $1.98/call → $0.37/call (81% reduction on Anthropic costs). Latency: up to 90s polling delay eliminated — cards arrive the moment Claude generates them.

**7 implementation steps completed:**
1. `npm install pusher pusher-js` — both server and client SDKs installed
2. `src/lib/pusher.ts` — new Pusher server singleton (Next.js global pattern for hot-reload safety)
3. `src/app/api/pusher/auth/route.ts` — new private channel auth endpoint; validates Supabase session + UUID format + call ownership before signing Pusher auth token
4. `src/app/api/wingman/poll/route.ts` — now pushes `scorecard-update` and `signal-card` events via Pusher; returns `{ ok: true }` instead of full parsed response
5. `src/app/api/wingman/kb-signal/route.ts` — now accepts `call_id`, pushes `signal-card` via Pusher with `source: "kb"`, returns `{ ok: true }` on all paths
6. `src/hooks/useWingmanPoller.ts` — subscribes to `private-wingman-call-{callId}` Pusher channel; handles `signal-card` and `scorecard-update` events; simplified `executePoll` (no response body processing); `runKBCheck` updated to include `call_id` and truly fire-and-forget
7. Railway env vars added: `PUSHER_APP_ID`, `PUSHER_KEY`, `PUSHER_SECRET`, `PUSHER_CLUSTER`, `NEXT_PUBLIC_PUSHER_KEY`, `NEXT_PUBLIC_PUSHER_CLUSTER`

**TypeScript verified:** `npx tsc --noEmit` returned zero errors across the full project.

**Critical bug caught during review (TDZ):** Initial draft placed the Pusher subscription `useEffect` (which has `fireSignal` in its dep array) BEFORE `const fireSignal = useCallback(...)` in the component body. React dep arrays evaluate immediately during render — `fireSignal` would have been in the temporal dead zone → `ReferenceError` on every render. Fixed by placing the subscription effect after `dismissSignal`.
