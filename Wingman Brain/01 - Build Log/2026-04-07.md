# Build Log — 2026-04-07

---

## What Got Built Today

- **Signal cards now fire on keyword triggers.** `fireSignal(keywordHit)` was being called correctly to detect objections but the result was silently discarded — never passed to `fireSignal()`. Fixed in `useWingmanPoller.ts:addChunk`. Confirmed working on a real test call: prospect said "this is too expensive" and a signal card fired.

- **Keyword signals bypass the 90-second cooldown.** A prospect raising a new objection is always more urgent than what's on screen. Keyword-triggered and Alert signals now interrupt the cooldown and any currently displayed card. Poll-based nudges still respect the 90s cooldown.

- **AbortController added to `executePoll`.** A hung Anthropic request with no timeout would leave `isPollingRef = true` forever, stalling the entire poll loop until app restart. Added a 10-second abort timeout — hung requests now fail gracefully and retry on next poll.

- **Full JSON schema added to Claude system prompt.** The poll path was not returning a correctly structured signal card object. Added explicit schema to the system prompt so Claude Haiku outputs the right shape every time.

- **Prospect name auto-detected from transcript.** First speaker who isn't the rep (compared against their Zoom display name from Settings) is identified as the prospect. Name is saved to `calls.prospect_name` on call end via session PATCH. Resets cleanly on each new call so a stale name from a previous call never carries forward.

- **Live/Processing skeleton added to dashboard.** Green "Live Call in Progress" skeleton shows while recording. Switches to grey "Processing call..." after call ends. Clears only when both `outcome` AND `summary` are populated — user sees the full debrief entry when the skeleton disappears, no hard refresh needed. Safety valve reduced from 10 minutes to 2 minutes if post-call job fails.

- **Disposition save fixed.** `hud-outcome/route.ts` was calling `supabase.auth.getUser()` without the bearer token — always returned 401 on the server. Fixed to pass the token: `getUser(token)`.

- **`handleEndCall` hardened with try/finally.** `isEndingRef` now always resets even if `flushBuffer` throws. `setPendingOutcome` moved after the `callId` check — no ghost skeleton on empty sessions that end immediately.

- **IPC bridge added for disposition → dashboard refresh.** `onOutcomeUpdated` / `offOutcomeUpdated` added to `preload.ts` and `main.ts`. Dashboard now refreshes the flight log entry in real time when the HUD outcome card is submitted — no page refresh needed.

- **Transcript deduplication fixed.** Recall.ai was firing the same utterance 7–9x. Root cause: listener stacking across call sessions + SDK-level duplicates. Fix: `realtimeListenerRegistered` flag ensures the realtime-event delegate is registered only once per app session. Dedup logic changed from a 500ms time window to last-text-per-speaker — only emits when the speaker's text actually changes.

- **Poll chunk size limit raised 10K → 50K.** With broken dedup the buffer was growing to 57K+ chars and getting rejected with a 400. With correct dedup, chunks are well under 1K per poll. The 50K cap is a safety net.

- **"No Show" and "Other" disposition bug fixed.** Database `calls_outcome_check` constraint didn't include those values but the HUD had both as options. SQL migration run — constraint updated.

- **CLAUDE.md updated.** Added "The Plan Review Loop" rule: all implementation plans must go through internal revision rounds before being presented to Sebastian. Only the final battle-tested plan gets shown.

## Decisions Made and Why

| Decision | Reason |
|----------|--------|
| Keyword signals bypass 90s cooldown | A prospect raising an objection mid-call is always time-sensitive. Suppressing it because a card fired 60 seconds ago would let money walk out the door. Poll-based nudges (lower urgency) still respect the cooldown. |
| Prospect name detected from transcript, not manual input | Rep shouldn't have to type anything. First non-rep speaker is the prospect in a 1:1 sales call. Simple, automatic, resets per call. |
| Skeleton clears on `outcome` AND `summary`, not just `outcome` | Clearing early meant the user saw an empty debrief card and had to refresh. Waiting for both fields means the entry is fully populated when it appears — better UX, no confusion. |
