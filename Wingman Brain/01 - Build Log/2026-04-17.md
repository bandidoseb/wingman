### Junction Table Architecture (kb_prospect_triggers)
- **Root cause identified:** the old `prospect_embedding` was created by concatenating 30+ trigger phrases into one block and embedding the whole thing. This "diluted" the embedding into a blurry average — similarity scores for correct matches were 0.38 instead of 0.72+. The search was finding the right techniques; the scores were just too low to pass the threshold.
- **Architecture decision:** junction table (`kb_prospect_triggers`) — one row per trigger phrase, each with its own crisp embedding. "Financial Objection Isolation" gets ~30 individual rows instead of one averaged vector.
- **Migration 008 built and run** — `kb_prospect_triggers` table created with `ON DELETE CASCADE` FK to `kb_signal_card_entries`. New RPC `search_kb_by_trigger` uses `DISTINCT ON (entry_id)` to find the best-matching trigger per technique, then returns top N techniques. Also returns `matched_trigger` so Railway logs show exactly which trigger phrase fired each card.
- **split-triggers.js built and run** — one-time backfill script. Split all 215 entries' prospect_triggers text into individual lines, embedded each phrase separately (100 per OpenAI batch), inserted 6,554 rows into `kb_prospect_triggers`. Cost: $0.0009. Time: ~90 seconds.
- **HNSW index created** — IVFFlat failed (memory limit on Supabase free tier). Switched to HNSW (`m=16, ef_construction=64`) which is actually the better algorithm: faster queries, no memory constraint during build, and handles table growth automatically.
- **ingest.js updated** — future video ingestion now automatically populates `kb_prospect_triggers` alongside `kb_signal_card_entries`. The delete step already cleans up old trigger rows via CASCADE. One URL in → both tables populated.
- **knowledge-search.ts updated** — now calls `search_kb_by_trigger` RPC instead of `search_kb_signal_card_entries`. Threshold set to 0.65 (calibration showed correct matches scoring 0.65–0.88 with per-phrase embeddings). Added 5-second `AbortController` timeout on the OpenAI embed fetch (fixes Issue #27).

## Decisions Made

- **Junction table over single-column diluted embedding** — Sebastian correctly identified that cramming 30 phrases into one vector was architecturally wrong. Per-phrase rows are the correct approach.
- **Stage filtering rejected** — initially proposed as an accuracy enhancement alongside the junction table. Rejected after stress-testing: stage detection is poll-based (can be stale), and objections transcend stage boundaries. A stale stage would suppress the right card at the wrong moment.
- **HNSW over IVFFlat** — forced by Supabase free tier memory limit, but HNSW is genuinely the better algorithm for this use case.
- **Threshold set to 0.65** — calibration showed correct matches scoring 0.65–0.88 with per-phrase embeddings. 0.65 catches all critical signal moments including pain admissions and past-failure objections.
