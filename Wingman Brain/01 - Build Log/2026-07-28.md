## 2. v0.1.29 SHIPPED (Session 1 of Track 1) ✅

Five sessions of held-local work: summarizer Cole-brain redesign · voice Phase 0 · Flight Recorder + Owner dashboard · post-call flow (pill morph, AI outcome auto-detect, deep-link) · bugs #52/#53 · confrontation dial (pinned + inert).

**Two review rounds before merge caught three things:**
1. 🔴 **Permanent "Debrief ready" pill over a LIVE call.** An auto-stop (inactivity / 2-hr) shows an amber safety pill, but the renderer's end-call PATCH re-emits `call:ended` WITH a callId up to ~10s later, morphing it into a persistent debrief pill while the rep is still on the meeting — and cancelling every timer that would hide it. Fixed with a **`hubSafetyClaimed` latch** (a `hubPhase` check is insufficient: the amber pill self-fades to `hidden` first, so a slow-network event arrives when the phase no longer says `safety`).
2. 🔴 **Post-call polling was re-running the full dashboard load every 2s.** The list query pulled `call_transcript(*)` for 20 calls (**a real 19-min call = 432 rows**, ~23/min) and both pollers `router.refresh()`'d it — **~180MB of Supabase traffic per call ended**, ~180GB/mo at 10 Test Pilots. Fixed: transcripts dropped from the list query and fetched on detail-open; new light `GET /api/calls/[id]` (~1KB; `?include=transcript` for the detail shape) backs both polls, firing ONE real refresh when the debrief lands. **~2000× reduction.**
3. 🔴 **Self-inflicted regression:** dropping transcripts from the list starved "Ask Wingman" of its transcript context — it would have silently coached from the summary alone. `sendCallMessage` now grafts the cached transcript back in.

**Merge snag:** PR #53 was squash-merged to main, so the branch's *identical* Live Hub work conflicted (12 HUD + 3 doc). Every conflict inspected: branch was a strict superset in 11, and the 12th was the deliberate post-call change (pill MORPHS instead of hiding). Resolved file came out byte-identical to the branch's HEAD. **Lesson: don't let a branch sit unmerged — the conflict debt is the cost.**

**DB:** `011_outcome_source.sql` added (column confirmed present in prod — the file exists so a rebuilt env can't silently break, the Known Issue #50 trap). `010_card_style.sql` intentionally **NOT run** — nothing in the shipping path reads `card_style`, verified by grep; the dial is inert.

## 4. THE DAY'S REAL LESSON — three review rounds on a two-bug fix

**Round 1 → BLOCK.** The stuck-pill fix keyed off `call.duration != null` as proof the transcript flush had finished. **No client has ever written `duration`** — the branch could never execute. It would have shipped as dead code that *looked* fixed in the changelog. Worst category of bug.
**Round 1 → BLOCK (second).** The Ask Wingman fix asserted "nothing was captured" from an empty `call_transcript` array — but list rows stopped carrying transcripts *that same day*, so `[]` usually means "not loaded", including while clicking through from the generating pill. It would have had Wingman **deny a real call happened**, with its own debrief above it in the same prompt. Worse than the bug it fixed.
**Round 2 → APPROVE WITH FIXES.** Caught that `clearHudSafetyHide()` on the new `"none"` phase **broke a safety net**: that message comes from the DASHBOARD renderer and proves nothing about the HUD renderer, which is the exact thing the 7-min net guards — a hung HUD would strand the overlay on screen forever. Also caught the two surfaces contradicting each other ("no transcript captured" vs "may still be saving, try reopening" → rep loops).

**Typecheck and 194 passing tests said everything was fine every single time.** None of these are catchable by the deterministic gates. This is the whole argument for the fresh-context adversarial review — and for the dogfood session sitting BEFORE Test Pilots.

**Final shape of the fixes:** the server reports **facts** (`transcriptRows`), never a verdict — it cannot distinguish "no rows ever" from "no rows yet". The clients own the judgment because only they know when the call ended: zero rows AND 30s elapsed (`NO_DEBRIEF_GRACE_MS`, 3× flushBuffer's 10s abort cap, 12× faster than the dead-man timer). The coach gets three states — **present / proven-empty / unknown** — and only proven-empty earns the hard "nothing was captured" line.
**Version skew is safe:** v0.1.29 rejects the unknown `"none"` phase with warn+return, so installed apps degrade to today's 6-min timer. Web half live now; HUD half lands with the next desktop release.

## 5. CARD DOCTRINE DECIDED (all → voice week, `tasks/launch-plan.md` Session 3–5)

Started from Sebastian's question — *how good is ↓ dig early in a call?* — and ended in a doctrine.

**Claude was WRONG twice and corrected on the record:**
1. Claimed the dig arrow's contract is "go deeper on what they just said." **It isn't** — the prompt says *"the rep's ↓ press asks: what's the best question to ask right now?"* and explicitly handles BOTH modes (⬜ open belief → OPENING question; 🟡 partial → chunk down).
2. Claimed the cold-open case needed building. **It already exists** — the prompt says *"an early call is a reason to START discovery, never a reason to stay silent"* and the no-summary fallback tells the model to ask an opening question grounded in the transcript. `"Start discovery."` only ever replaces a **take-the-close** on a cold ladder (the #52 gate) — it never replaces a real question.

**The Cole Gordon framing (Sebastian flagged it for the WEBSITE — memory `project_positioning_gutter_moments`):** the opening is where a closer needs help LEAST — most rehearsed, most rep-specific, and nothing has happened yet to be smart about. The gutter is **minute 18** (vague answer accepted instead of chunked down), **minute 34** (the real objection in a costume), **minute 41** (pain + desire built, doesn't know they're allowed to close). Handing a confident closer a generic opener is worse than handing them nothing — that's rules #10/#11 breaking at the exact moment the prospect forms a first impression.

**LOCKED RULES for ↓ early in a call:**
1. The test is **"has the prospect revealed anything real?"** — NEVER "how many minutes in." Real = problem, goal, number, frustration, constraint, what they've tried, why they took the call. Not real = greetings, location, weather, tech check, scheduling, "got your book."
2. Something real on the table → **dig it**, anchored to their exact words. Same at minute 2 and minute 40.
3. Nothing real yet → **Wingman admits it has nothing.** It may NEVER invent a discovery question from its own head. No anchor → no card.
4. Never take-the-close on a cold ladder (#52, shipped).
5. The quiet state is **honest, not instructional**: `"Nothing to work with yet."` replaces `"Start discovery."` (Rejected: *"Still listening."* — Sebastian: reads like a loading spinner on a terminal state.)

**Doctrine:** *Wingman speaks only when it knows something the rep doesn't.* At minute 1 with nothing said, it doesn't — and saying so IS the feature. **The work is SUBTRACTION, not addition**: two prompt instructions currently *command* a question unconditionally (`dig-prompt.mjs` ~line 78 + the `buildDigUserSegments` no-summary fallback). Both must change together.

**RENAME (Sebastian-locked):** ↓ "Dig Deeper" → **"Discover"** (asking questions IS discovery; "Deeper" misdescribes the arrow and actively misled Claude while reading the code). **← stays "Answer"** — the "Explain" idea only existed to dodge an Ask/Answer collision, which picking Discover removed. Final compass: **↑ Objection · ← Answer · → Close · ↓ Discover**. **USER-FACING LABELS ONLY** — do NOT rename `dig-prompt.mjs` / `DIG_SYSTEM_PROMPT` / eval identifiers (zero user value, real risk to the eval gates pre-launch).

**EXHAUSTION DETECTION pulled from the parking lot → PRE-BETA REQUIRED** (Sebastian). Reps will mash ↓; today the ladder redirects once a belief locks ✅ but there's no sense of exhaustion WITHIN a belief — the third question about their timeline is one too many, and the prospect feels interrogated.
