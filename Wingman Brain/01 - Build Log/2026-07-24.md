# Session 2 — Bugs #52 + #53 FIXED (Flight Recorder's first catches) + Post-Call Flow redesign locked

## What shipped (committed local, `feat/confrontation-dial`)

### 🐛 #53 — → Close press froze the whole compass ~40s — FIXED + LIVE-VERIFIED ✅
Root cause (proven from Flight Recorder call 6999e874): the dashboard window is HIDDEN behind Zoom
during calls with **no `backgroundThrottling: false`** → Chromium batches a hidden window's chained
timers to ~1 wake/min → `summarizeNow()`'s chained-120ms poll loop never woke to check its own 8s
cap → the shared `isGeneratingRef` busy-lock froze the compass 42s; every press dropped "generating".
**Bigger blast radius:** the same throttling was silently delaying the 25s transcript saves + 2-min
summarizer on EVERY call. Fix (plan-reviewed, 4 findings folded in):
1. `backgroundThrottling: false` on mainWindow (electron/main.ts) — un-throttles the whole live-call
   engine; ships to packaged apps at v0.1.29.
2. `summarizeNow` rewritten EVENT-DRIVEN (useWingmanPoller.ts): executeSummarize publishes a
   completion promise synchronously with its mutex, resolves it in `finally`; waiters
   `Promise.race([completion, single 8s timeout])` (timer cleared in finally — no chained timers).
   Ships via Railway → protects EXISTING packaged apps.
3. Fresh-enough fast path: `lastSummaryAtRef` stamped on any ok response (mirrors the server's 30s
   floor); a close press with a <30s-old summary answers INSTANTLY, killing the doomed-429 storm.
**Live-verified** (call 6bca0cab, 08:31): close press → readiness chip in **3ms** (was 42,000ms);
zero dropped presses across 4 rapid presses.

### 🐛 #52 — ↓ Dig said "go for the close" with ZERO discovery — FIXED (eval-proven) ✅
Root cause (call 928e4249): the dig prompt offers Sonnet only two outputs — dig, or {null,null} =
take-close; on a degenerate call (empty/all-⬜ ladder) null/null is its only escape hatch and the
route unconditionally rendered "They're ready — go for the close." Fix, two layers + eval:
1. Deterministic server gate: new `isColdLadder()` in close-readiness.mjs (missing summary OR
   `scoreReadiness().cold` — same engine as the → chip, arrows can't disagree). Cold → renders
   **"Start discovery."** (Sebastian-locked wording). Gate is COLD-ONLY, deliberately narrower than
   "not-ready" — plan-reviewer caught that a not-ready gate would clobber the verbal-readiness
   doctrine ("how do we start?" with only Pain 🟡 → take the close); a unit test pins the override.
2. Additive prompt rule (dig-prompt.mjs WHEN NOT TO DIG): never null/null before discovery starts —
   ask the opening Pain question.
3. New dig-eval fixture #15 (the exact bug shape) digs 3/3; full corpus GATE PASS (15/15 contract,
   tonality 4.62, 0 fabrication, take-close fixtures intact). 7 new unit tests
   (tests/wingman/close-readiness-gate.test.ts). Honest note: the live smoke test never reached the
   new gate (no finalized speech → older empty-transcript branch answered) — eval+unit proof only.
