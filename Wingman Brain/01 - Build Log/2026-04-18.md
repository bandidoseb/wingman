## What Was Built

### 1. Mission Intel Deep Dive (main feature)
**Files:** `src/app/api/ai/chat/route.ts`, `src/components/dashboard/FlightLogTab.tsx`

When a user asks about a specific call in global chat, Wingman now walks them through a 3-turn confirmation flow and then seamlessly becomes a full per-call coaching session — all inside the same modal. No navigation, no button.

**The flow:**
- Turn 1 (Step 1): User asks about a call → Claude identifies best match, asks for confirmation. No marker.
- Turn 2 (Step 2): User confirms → Claude offers the dive, ends reply with `CALL_MATCH:{call_id, name, date}`. Server strips marker, returns `callSuggestion`. Client stores silently as `pendingCallSuggestion` — nothing shown.
- Turn 3 (Step 3): User accepts → Claude says "reading the transcript now…" and ends reply with `DIVE_NOW`. Server detects with case-insensitive regex, fetches full transcript (2 auto-retries, 500ms delay, user_id guard), returns `diveReady: { openerReply, callData }`. Client shows staggered messages, waits 2s, shows personalized opener, switches modal to single-call mode.

**Key decisions:**
- No transcript word cap — deleted `capTranscript()` entirely. 2-hour hard stop is the natural ceiling.
- No CTA button — entire flow stays inside global chat modal.
- Auto-retry (2x, 500ms) before showing error. Error preserves `pendingCallSuggestion` so user can say "try again."
- UUID validation on all `pendingCallId` inputs (`UUID_REGEX`).
- `.eq("user_id", user.id)` on all transcript fetches — critical security guard.
- State (`pendingCallSuggestion`, `activeSingleCall`, `singleCallHistoryRef`) clears on every modal close.
- Prompt caching: `cache_control: ephemeral` on the context block in single_call mode. ~90% cheaper on repeated questions about the same call. `anthropic-beta` header added conditionally.

### 3. Modal scroll fix
**File:** `src/components/dashboard/FlightLogTab.tsx`

Removed `justifyContent: "flex-end"` from the modal message container. Added a `flex: 1` spacer div above the messages instead. Messages pin to the bottom when chat is short; when messages overflow, scroll works normally. (The original CSS caused overflow to go upward, making it unscrollable.)
