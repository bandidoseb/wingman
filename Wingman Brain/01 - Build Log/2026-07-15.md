## ✅ Shipped this session — [PR #50](https://github.com/bandidoseb/wingman/pull/50) `feat/close-readiness-chip` (OPEN at wrap; CI + security-review running)

**The feature:** pressing **→ Close** surfaces a deterministic readiness chip driven by the live Belief Ladder, so the rep sees at a glance whether they've earned the pitch.

### What got built
- **NEW `src/lib/wingman/close-readiness.mjs`** — pure scoring (Belief Ladder text → 1 of 4 states + gap). `.mjs` so the eval imports the exact shipping logic (same anti-drift pattern as `dig-prompt.mjs`). NO AI, client-scored.
- **NEW `scripts/test-close-readiness.mjs`** — 28/28 gate (false-green, evidence-glyph, legend/quote-line exclusion, VS16 emoji, duplicate lines, cold-start).
- **4-step chip:** 🔴 Not Ready · 🟠 Continue Discovery · 🟢 Almost Ready · 🟢 Ready to Pitch. Cold start (nothing covered) → "Discovery hasn't started yet" (no fake gap).
- **Promoted action CTAs:** colored **↓ Dig deeper** (readiness) / **↑ Next move** (objection flow) buttons with a keycap — work by **mouse click OR the arrow key** (click reuses the exact `wingman:menu-pick` path).
- **✕-circle dismiss** on every card (replaced the "got it" button — Sebastian picked this from a 5-option artifact comparison).
- **`summarizeNow()`** in `useWingmanPoller.ts` — force-fresh belief summary on press (reuses the in-flight summarize, never double-calls Sonnet).
- **↓-key arming** in `electron/main.ts` — while a readiness chip with a gap shows, `Down` is armed as a direct dig pick, with the same collision-safety invariant as Phase C flow mode (disarm before compass/flow claim Down; disarm on replacing card / call-end / dismiss / safety timer).

### Locked decisions (Sebastian)
- **Scoring — conservative, never a false "Ready":** 4 GAT beliefs (Pain · Can't-DIY · Cost · Desire) locked + Money + Decision-maker confirmed = Ready. **ANY live objection (⚠️) anywhere blocks the green states** (the plan-reviewer caught the original draft letting a Trust/Money ⚠️ still show green — the false-green bug).
- **Force-fresh summary on press** (Sebastian: a great last-2-min shouldn't be missed) — instant when nothing new, ~2–4s "Reading the close" pill only when there's new speech to score.
- **Cold start shows an honest note**, not a 2-item gap (his live-test catch — it listed only 2 beliefs when nothing had been covered).
- **Reuse the existing `BELIEF_DISPLAY` pillar names** (Core Problem / Can't DIY / Cost of Waiting / Dream Outcome / Investment / Who's Deciding / Why You) — one vocabulary across dig tags + readiness.
- **"Got it" → circled ✕, top-right, on every card** (opaque stroke + element `opacity` so the crossover isn't a brighter dot).

## 🆕 Decided this session — the **Wingman Live Hub** (next dedicated session)

Live-testing #2 exposed three real HUD problems: (1) the **top-center is crowded** — compass + signal card + "thinking" pill all render in the same spot and overlap; (2) the **live dot is basically invisible**; (3) after Deploy, **"Starting" flashes then vanishes** with no "Wingman is running" confirmation.

Sebastian's fix (agreed): a **Granola-style floating "Wingman live" pill** — draggable, branded (Wingman logo), always-on-while-live, **content-protected** (invisible to prospect), that on hover/click surfaces a **mini-settings shell** (signal-card word color + a new **formality** control). He explicitly wants a **REAL listening waveform** — open research problem, because the HUD doesn't currently have the live audio stream (Recall captures it server-side).

This one build **absorbs roadmap #3 (card-color customizer) + #4 (live-indicator, un-skipped after live-test) + the new formality control**. Full spec: memory `project_wingman_live_hub.md`. **Order: ship #2 first (done), then the hub.**

> Note: #4 live-indicator was **skipped earlier this session** ("the dot is fine") then **un-skipped** once live-testing proved it wasn't — a clean reversal, folded into the hub.
