# 2026-06-10 — #39 SOLVED: the compass bug that survived three sessions (PR #13 merged)

## Summary
Found and fixed the **root cause of #39** (compass never rendered) — and it wasn't the compass at all. A dead `window.hud.onSignalDismiss()` call, sitting in the HUD since the **initial commit**, referenced a method the `hud` preload bridge never exposed. The load-time `TypeError` silently killed every IPC registration below it: the compass (#39), the auto-stop reason toast, the 2-hour cap warning, and the stage-pill init — all dead on every call, ever. One deleted line un-broke all four. **Live-verified by Sebastian on a real Zoom call. PR #13 merged to main.** Also fixed #40 (dismiss animations glitching up-left) found during the re-test, and locked two product decisions.

## How it was found (the method matters)
Two prior sessions verified the compass code path statically and found "no code bug" — because the compass code WAS correct. This session changed strategy: stop re-reading code, **instrument every hop** (Up press → main send → preload relay → HUD receipt → computed-style/paint readback, all printed to the dev terminal via a new `hud:log` relay) + **auto-open detached DevTools on the HUD in dev** (the overlay is frameless + click-through — it had NO inspectable console until now; that blindness is why the bug kept escaping). The DevTools window exposed the `TypeError` **on launch, before a single test call.**

Verification rigor: machine-checked (`comm -23`) that `onSignalDismiss` was the ONLY method the HUD calls that the bridge doesn't expose; confirmed main never sends `signal:dismiss` to the HUD across all 20 `hudWindow…send` sites (the listener was dead plumbing from the retired autonomous-card model); proved the renderer half healthy in a plain-browser preview before touching anything.
