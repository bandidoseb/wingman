## 1. Dark mode — fixed at ONE token, plus a bug the brief didn't know about

**The rule we had backwards:** in dark mode elevation is expressed as LIGHTNESS, and you cannot
go DOWN — `--paper` is already near the floor, so a "recessed" surface must go **UP**.
`--surface-sunken` sat at `#100F0D`, *below the page background*, which is why every input, tab
track, hover fill and keycap read as a black hole.

```
--surface-sunken (dark)   #100F0D  →  #2C2B25
```

Ladder is monotonic again: `#171613` page → `#201F1B` card → `#2C2B25` field. Step **1.162:1**
vs light's 1.158:1, so neither theme feels flatter. **One token, every screen.**

**⭐ The finding the written brief did NOT contain — and Sebastian caught it by eye.**
`src/components/ui/Card.tsx` hardcoded its dark background to an **iOS system gray**:

| | R−B | reads as |
|---|---|---|
| legacy `Card` in dark | **−2** | COOL / bluish |
| `--surface` (Home, Coach) | **+5** | WARM / brownish |

That is exactly his *"it's like a bluish gray, and then on the homepage it's like a brownish
gray."* **Seven tabs imported that card.** One line fixed all of them. Same family:
`SectionLabel`'s dark gray measured **2.37:1** — effectively invisible.

**Lesson: when Sebastian describes a colour difference in words, measure the hue channels.**
He is describing something real.

Also: `--ink-3` → `#8A867C` (min contrast 2.79 → 3.91:1) · new **`--knob`** token (switch thumbs
stay near-white in BOTH themes — same "must not flip" class as `--scrim`) · `Toggle` rebuilt as a
real `<button role="switch">`.

Rules written up as **Design Language §3f**: elevation direction, matched step sizes,
never-pure-black, field treatment, a measured contrast table, accent desaturation, must-not-flip
tokens, and the track/thumb composition trap.

## 3. Three LIVE Coach bugs, found while planning the unified bar

The plan review turned up bugs that had nothing to do with the feature being planned.

**PR 1 — the dive handoff has never worked, and it burned quota per message.**
`/api/ai/chat` selects the dive call **without an `id`**, so `Coach.tsx`'s branch keyed on
`diveReady.callData.id` was always false. On Home, "yes, dive into that call" silently did
nothing. Worse: `setSuggestion(null)` lived *inside* that dead branch, so the suggestion never
cleared → `pendingCallId` rode every later send → the model re-fired `DIVE_NOW` → each message
re-read the full row **plus the whole transcript** and paid for another Sonnet call and another
quota decrement. Invisibly, until reload.

It hid because `res.json()` is `any`: the route said `callData`, the client read `callData.id`,
and nothing connected them. **Fix is a SHARED `ChatDiveReady` type imported by both ends** —
mutation-verified by renaming the key and watching both files fail to compile.

**PR 2 — the quota counter.** (a) Flight Log's two chat surfaces spent the same daily allowance
and never reported it → surprise 429 with headroom showing. (b) On a 429 the client set its own
counter to the cap → the sidebar could render **"23 of 20 used"** and **"-3 left"**. (c)
`baseline` lived in a `useRef` captured once, so a tab left open past UTC midnight stayed
**locked at the cap on a fresh day**.

**PR 3 — state lift, zero visible change.** `CoachProvider` now holds the transcript cache and
this session's outcome confirmations, so the bar (PR 4) can reach them. Deliberately *below*
DashboardClient so its updates never re-render the live-call handlers or the pill state machine.
The two outcome maps had **different shapes** — Home's flipped `outcome_source` to `"manual"` so
stats counted it, Flight Log's was a bare string feeding the "N/M closed" header — so merging
them carelessly would have silently changed that number.

## 4. Two bugs I caused, and what they have in common

**One number written in two files WILL desync.** The collapsed-rail width lived in `Sidebar.tsx`
AND `DashboardClient.tsx` as two hardcoded copies. I changed one (56 → 80) and not the other, so
the two animated toward endpoints 24px apart and the content finished under the rail — which
Sebastian reported as *"the animation is jumpy."* Fixed at the cause: one exported constant.

**`npm run build` as a verification gate killed his running dev server** — twice, with the lesson
already written down. A production build replaces the chunks in `.next`; his `electron:dev` runs
against the same directory, so his loaded app died with `Cannot find module './5611.js'` on a
dashboard that was fine. Stopping *my* preview server was never enough — his terminal has its own.
**Fixed structurally: `npm run build:verify` builds into a throwaway dir** (proven with a sentinel
file). Plain `npm run build` is for Railway and for Sebastian, not for me.

**PR 5 added as a brief:** chain-of-thought progress. Today the dive shows three bouncing dots.
The constraint that decides the design: `/api/ai/chat` is **not streamed**, so the client has zero
visibility into server phases — a chain-of-thought bolted on now could only be **invented steps on
timers**, which is the fake-progress pattern Rule #11 exists to prevent. So PR 5 is really "make
the route stream its phases" (precedent: `kb-signal` already streams SSE). Real phases available:
searching the KB, thinking, finding the call, reading the transcript, **"Retrying (2 of 3)"**
(happens today and is completely invisible — a ~1.5s stall just looks frozen), and the honest
"couldn't find that call".
