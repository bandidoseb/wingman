## Review catches worth remembering

`wingman-reviewer` ran on every diff. The high-value ones:

- 🔴 **`min-h-` doesn't bound a flex child.** The chat had `min-h-[calc(100vh-96px)]`, so at 40 messages
  the composer sat at y=2022 in a 794px viewport — **the input walks off-screen and you must scroll
  the page to type.** Needed a definite height. Re-measured after: 0px drift.
- **Stale-`calls` leak** — confirmations applied only to today's rows, so the Coach answered
  "what's my close rate" ignoring a ✓ clicked two seconds earlier.
- **Tab switch destroyed the conversation** — including via the Coach's OWN "Open X in Flight Log →"
  handoff. State hoisted into DashboardClient.
- **Counter double-counted after `router.refresh()`**, halving the real quota.
- Two of my own bugs, caught by measuring rather than reasoning: clicking the chat bar **silently ate
  the first keystrokes** (React rebuilt the composer), and prompt-kit's typing dots were a **static
  image** (it ships the animation class but no keyframes).

## Process lessons

1. **Never run `npm run build` while the dev server is running.** It overwrites `.next`; the running
   server then serves a stylesheet-less page that looks catastrophically broken. Cost Sebastian a
   "welp, it looks broken" moment. Stop → build → clear → start.
2. **Don't trust a browser screenshot taken right after a DOM/theme change.** It returns stale frames.
   Twice I called a rendering regression that measurement disproved. Read computed styles first.
3. When evidence contradicts itself twice, **restart the dev server** before debugging further — I
   burned a long stretch chasing a stale bundle.

## 🔴 NEXT SESSION — start with RESEARCH: `tasks/plan-dark-mode.md`

Sebastian's dark-mode feedback (verbatim in the brief): **Home is the reference.** The Sales DNA input
fields are "a completely different dark black color" while Home's chat box is "that light color I
like."

**Already diagnosed — one token, not a per-screen problem.** In light mode recessed surfaces go
*darker*; in dark mode that **inverts** (lighter = higher elevation). Our dark `--surface-sunken`
(`#100F0D`) is DARKER than `--surface` (`#201F1B`) — backwards, and it's also used for hover fills,
tab tracks and progress tracks, so it's everywhere.

The brief lists the research questions (elevation steps, why not pure black, field treatment, WCAG
contrast on dark, accent desaturation) and says to write the answers into the Design Language doc
before changing values. **If the fix changes Home, the fix is wrong.**

Then: **SettingsTab (75 literals)** — biggest remaining and the natural home for the light/dark toggle,
which doesn't exist yet (today you switch via localStorage).
