## What Was Planned

### The Core Problem Being Solved
KB was returning 0 matches on every live call search. Root cause: entries were written from the coach's perspective, but search queries are raw prospect speech. Semantic mismatch. Similarity scores were landing at 0.31 — nowhere near the 0.65 threshold.

```
Stored:   "When a prospect raises a price concern, use value reframing..."
Searched: "this is too expensive"
Score:    0.31 — no match, no card fires
```

### The Plan Review Loop
Went through Plans A → B → C → hardened Plan C before touching any code. Then ran an adversarial subagent specifically tasked to break the plan. Found 24 real issues including 5 that would have caused silent production failures:

**Critical issues caught before building:**
1. **Production KB blackout during re-ingestion** — old plan used bulk DELETE before re-ingestion started. A crash would leave zero results for hours. Fixed: per-source delete (happens AFTER successful extraction for that source).
2. **`quality_score` NULL excluded all existing entries** — new RPC filters `quality_score IN ('high', 'medium')`. Without DEFAULT 'medium', every existing entry would return zero results the moment the migration ran. Fixed: `DEFAULT 'medium'` + backfill UPDATE.
3. **`exact_script` and `why_it_works` never reached Haiku** — RPC RETURNS TABLE didn't include them. Fields were ingested but silently ignored. Fixed: added to RPC RETURNS TABLE.
4. **`--force` flag missing** — all 38 sources are status='complete'. Without force flag, re-ingestion script would silently skip all of them and do nothing. Fixed: `--force` flag required for re-ingestion.
5. **No timeout on Sonnet Pass 2** — a hung network call would stall the entire queue indefinitely. Fixed: 5-minute AbortController timeout.
6. **Similarity threshold 0.72 was fictional** — it's a client-side variable in knowledge-search.ts, not hardcoded in the RPC. Both must be updated together or it has no effect.
7. **Duplicate check would skip all 38 sources** — existing ingest.js has `if (status === 'complete') return duplicate`. All 37 sources are complete. The --force flag overrides this.

**Full adversarial review findings saved in:** `Wingman Brain/00 - Product/KB Ingestion Spec v2.md`

### 1. SQL Migration — `supabase/migrations/006_kb_v2.sql`
**Status: ✅ Run and verified in Supabase**

- Added 15 new columns to `kb_entries`:
  - `prospect_triggers` TEXT — 30+ prospect speech examples
  - `exact_script` TEXT — verbatim rep words
  - `situation` TEXT — one sentence context
  - `why_it_works` TEXT — the principle behind the technique
  - `call_stage` TEXT — with CHECK constraint (Rapport/Discovery/Press/Confirm/Pitch/Close)
  - `quality_score` TEXT DEFAULT 'medium' — with CHECK constraint (high/medium/low)
  - `content_type` TEXT
  - `prospect_embedding` vector(1536) — new primary search anchor
  - `sequence_*` columns (4) — future objection sequences
  - `trigger_speaker` TEXT DEFAULT 'prospect' — future rep monitoring
  - `rep_trigger_*` columns (2) — future rep monitoring
- Renamed `embedding` → `technique_embedding` (existing ivfflat index auto-updated by Postgres)
- Added CHECK constraints on quality_score, call_stage, trigger_speaker (typos now fail loudly at insert, not silently at query time)
- Backfilled existing entries: quality_score='medium', trigger_speaker='prospect' so they still appear in search during transition
- Dropped old search RPC, created new dual-vector weighted RPC:
  - 70% prospect_embedding + 30% technique_embedding
  - COALESCE handles NULL embeddings during transition window
  - Returns: id, technique_name, situation, exact_script, why_it_works, call_stage, quality_score, similarity
  - Fallback for old entries (NULL prospect_embedding): use technique_embedding at 0.65 threshold
- ivfflat index on prospect_embedding NOT created in migration — deferred to after re-ingestion

### 2. `knowledge-base/ingest.js` — Full Rewrite
**Status: ✅ Written, running**

The entire pipeline was rewritten from a single-pass Sonnet extraction to a 3-pass pipeline with dual embeddings.

**New architecture:**

**Startup sequence (every run):**
- Reset any sources stuck in 'processing' state (crashed previous runs)
- Validate API keys with test ping before spending anything
- Check which sources have cached transcripts (Whisper cost = $0 for cached)
- Print full cost breakdown and require y/n confirmation

**Per-source flow:**
```
1. Duplicate check (skipped with --force)
2. Fetch metadata (yt-dlp)
3. Check transcript cache → skip Whisper if cached
4. Pass 1: Content Intelligence (Haiku, 60s timeout)
5. Pass 2: Deep Extraction (Sonnet, 5-minute timeout, max_tokens: 16000)
6. Required field validation (technique_name, call_stage, situation, prospect_triggers, exact_script)
7. Pass 3: Quality Gate (Haiku per entry) + trigger count floor (< 20 = auto-discard)
8. Batch embed all passing entries (one OpenAI API call for all vectors)
9. Atomic embedding check (both must succeed or entry skipped)
10. Delete existing entries for this source
11. Insert new entries
12. Update kb_sources (status, entry_count, processing_cost)
```

**Key improvements over old ingest.js:**
- `--force` flag for re-ingestion
- Transcript cache (`knowledge-base/transcripts/{videoId}.txt`) — saves ~$4-5 on re-runs
- 5-minute AbortController timeout on Sonnet
- `max_tokens: 16000` on Sonnet (old default 8192 would truncate large videos mid-JSON)
- Batched OpenAI embeddings (one API call for all entries, not one per entry)
- Atomic dual embeddings (both succeed or entry is skipped — no partial records)
- Per-source delete (not bulk DELETE — old entries stay alive until source successfully rebuilds)
- Retry logic for 529 overloads: 10s → 30s → 60s between attempts (4 total)
- `ingest_warnings.log` for skipped/discarded entries
- CHECK constraints catch typos at insert time
- CLI entrypoint (node ingest.js --force) while still exporting ingestVideo() for server.js

## KB Quality Issues Found (QA by Sebastian)

While skimming entries in Supabase during ingestion, Sebastian found 3 categories of bad entries that slipped through the quality gate:

### Issue 1: Offer-Specific Exact Scripts
**Example:** `"Look, everything we do is in group format, however, instead of one call a week, we have five a week and I've never seen more than 10 people on one call..."`
**Problem:** This script contains the coach's specific offer details (5 calls/week, max 10 people). If a Wingman user has different offer structure, the card fires with completely wrong information. Rep says "we have five calls a week" when they only have one.
**Root cause:** Pass 3 prompt didn't check for offer-specific details.
**Fix needed:** Pass 3 prompt rule: if exact_script contains specific numbers, pricing, product names, or business details that belong to the coach's offer → score 'low'.

### Issue 2: Third-Person Prospect Triggers
**Example:** "They want to start a new business" instead of "I want to start a new business"
**Problem:** Prospect triggers must be first-person — the actual words coming out of the prospect's mouth. Third-person triggers don't match live transcript speech. The embedding won't match because real prospects don't talk like that.
**Root cause:** Pass 2 prompt says "natural spoken language" but Sonnet is sometimes defaulting to coach-description style.
**Fix needed:** Pass 2 prompt to explicitly state: "Write every prospect trigger in first person — exactly as the prospect would say it. Never third person. Never 'they want' or 'the prospect said'. Always 'I want' or 'I'm not sure' or 'what if I'."

### Issue 3: Non-Sales Content Extracted
**Example:** Prospect triggers like "How did I do today", "I want to track my progress", "I need to be more self-aware" with exact_script about sending an end-of-day report and rating yourself on physical/emotional/mental state.
**Problem:** Coach mentioned their personal daily productivity routine during the video. Sonnet extracted it as a "technique." Has zero application on a live sales call.
**Root cause:** Pass 2 extraction rules say "ignore motivational content" but didn't explicitly exclude personal habits/routines/mindset content.
**Fix needed:** Pass 2 rule: "Only extract techniques that are directly applicable on a live sales call — meaning either the rep says something TO the prospect, or the technique describes how to respond to something the prospect says or does. Personal habits, daily routines, mindset practices, and self-improvement advice are NOT sales techniques. Do not extract them."
