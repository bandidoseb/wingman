# 2026-06-21 — Kill the KB on live cards → context-driven objection prompt (Cole Gordon + live closers), Sonnet

**Type:** Strategy + prompt-engineering + research session. **No production code shipped** — all work is
decided + validated in offline harnesses; wiring is the next session. Big architectural shift.

---

## The question that started it
Sebastian: *is the "proprietary" high-ticket-sales KB actually useful for objection handling, or is it
just making Wingman slower? Can the AI handle objections well on its own?*

Honest read (senior-engineer): the KB of public YouTube sales advice is **not a moat** (Claude already
knows the canon), and the live path's forced-script rule (`knowledge-signal.ts`: *"base your headline
directly on that script"*) was **constraining** good cards toward mediocre retrieved scripts. The real
moat is the **per-rep / per-offer context** (the Belief Ladder), not the KB.

## What we did — proved it, didn't assume it
- **Blind A/B harness** (`scripts/kb-ab-*.mjs` + `tasks/kb-ab-test/grader.html`): 12 objections, 4 arms
  per objection — **A:** KB card (real path), **B:** Claude free (no KB), **C:** "like Jeremy Miner",
  **D:** "like Cole Gordon" — same context, blind, randomized. Built a clickable local grader too.
  *(Note: the grader had a 1-char quote-mismatch that blanked it — lesson logged in `tasks/lessons.md`:
  syntax-check generated HTML before handing it over.)*
- **Sebastian's read:** the KB cards were indistinguishable from / worse than no-KB, and the KB whiffed
  on ~1/12 even in test. **Decision: cut the KB from the live objection path; keep it for the Wingman
  Coach (Mission Intel) only.**
- **Key realization (his):** an objection handler is only as good as the *context* it's fed. A generic
  prompt = generic handles. The handle has to lean on what discovery already uncovered.

## The audit — Wingman's context capture is already Cole Gordon
Read the 3 Cole Gordon training PDFs Sebastian provided. **Wingman's live summary (`belief-ladder.ts`)
already tracks Cole's exact 7 beliefs** — Pain, Doubt (can't DIY), Cost (of inaction), Desire, Money,
Support (who decides), Trust (why you) — each graded, **plus** the gap (hell→heaven + $ goal + why),
the emotional "final straw," the core driver, and **verbatim quotes for tie-downs**. The hard part
(capturing context live, honestly graded) was already built (locked 2026-06-05, 5-trap test).

The doc's killer line: *"every objection traces back to one of the 7 beliefs."* So the handler's job =
**diagnose which belief is weak (Wingman already flags it: ⚠️/Weakest Link) → rebuild it with one
question anchored to what they already said.** The gap was never capture — it was *usage* (the old card
prompt received the summary but never mined it).

> Note: there are TWO context structures. **Belief Ladder summary** (`belief-ladder.ts`, rich, Cole's 7)
> is what objection handling uses + already receives. **LiveScorecard** (`LiveScorecard.tsx`, 4-checkpoint
> legacy: pain/timeline/finances/decision-maker) is a partial older thing, NOT in the objection path —
> leave it.

## The new objection prompt — built + validated
- Distilled the method to `knowledge-base/objection-transcripts/PLAYBOOK-SYNTHESIS.md` from **7 training
  videos** (4 Cole Gordon + 3 Matthew Ryder, deep-read) and **13 live-call transcripts** (8 JP Egan,
  Johnny Mau, 2 Christian Polk, Jeremy Miner, Tim Ray → `LIVE-CALL-FINDINGS.md`). Live practice CONFIRMS
  the architecture (a closer on-camera: *"now I have leverage… if you've got no problems, when they say
  'I need to think about it' you've got nothing to pull on"*).
- Prompt (`scripts/objection-prompt-test.mjs`): diagnose weak belief → **uncertainty-first** → pace +
  tie-down anchored to their stated outcome + a verbatim quote → **one human line** (no headline).
- Validated on the 12 context-rich scenarios — every card leans on a real discovery anchor (respects a
  genuinely-broke prospect, sees through "send me info," uses their own abandoned-plans history, etc.).

## Tonality pass (Sebastian's detailed feedback → the hard part)
- Killed AI throat-clearing ("real quick," "here's what I'm asking"), email-y constructions, garden-path
  sentences, obscure idioms ("ground it out"); enforced spoken word, contractions, ONE beat, calm
  authority. Folded permission-to-reframe ("can I share a perspective?") + de-gendered the spouse move.
- **Haiku has a stubborn wind-up tic** — kill one preamble, it substitutes another; prompt-only kept
  relocating it. **Tested the variable: it's the model.** Same prompt on **Sonnet** = clean, human, no
  tic, every flag fixed.
- **DECISION: objection card = Sonnet** (`claude-sonnet-4-6`). Latency: Sonnet ~2.1s typical vs Haiku
  ~1.7s (~0.4s more, one 6.2s tail spike). We bought the budget by cutting the KB; streaming hides the
  rest; tonality is the product here. (Sebastian's call.)

## Signal card UI change (decided)
Kill the headline on **all** signal cards. New shape: a tiny type-tag ("Objection handle" / whatever
arrow) + main text = the **first-person line** the rep says. (The new prompt already outputs one line.)
