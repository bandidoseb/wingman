## Code Change: Belief Ladder Token Cap 400 → 600

**File:** `src/lib/wingman/belief-ladder.ts`
**Change:** `BELIEF_LADDER_MAX_TOKENS = 400` → `600`

**Why:** Live logs showed `out=` values of 397–400 on virtually every tick. The model was hitting the ceiling. The scorecard template ends with Open Objections and Weakest Link — both likely truncated. Weakest Link is the most critical field for Phase 3 signal cards (it tells Haiku exactly what belief needs shoring up).

**Cost impact:** +~$0.05/call. Negligible.

**⚠️ This change is NOT yet on a branch/PR.** It was made in the working tree and needs to be included in the Phase 3 PR.

**What to watch:** After the next few live calls, check `out=` values in the `[summarize]` logs. If still hitting 580–600 consistently, raise to 700–800. If settling at 450–550, the cap is right. Documented in `Beta Tuning Parameters.md`.

## Phase 3 Design Decisions Locked

These were discussed and confirmed this session. The Phase 3 session needs to implement all of these.

### 1. Full scorecard → Haiku (not the 5-field snapshot)

**Current state:** `knowledge-signal.ts` receives a `ScorecardSnapshot` with 5 fields: `pain_detail`, `gold_moment`, `predicted_next_objection`, `objection_risk`, `prospect_anchors`.

**What it should be:** The full `liveSummary` text from the Belief Ladder (~600 tokens) passed directly. This includes:
- All 7 belief statuses (✅/🟡/⬜/⚠️)
- **Weakest Link** (the most important field — tells Haiku which belief to address)
- Verbatim prospect quotes (needed for tie-down language — system prompt already asks for this but the quotes aren't in the snapshot)
- The Gap section (current hell, desired heaven, $GOAL)
- Open objections

**Files to change in Phase 3:**
- `src/app/api/wingman/kb-signal/route.ts` — accept `live_summary` string instead of `scorecard_snapshot` object
- `src/lib/wingman/knowledge-signal.ts` — replace snapshot block with full scorecard text in the user message
- Client-side hotkey handler (Phase 3 new code) — send `liveSummary` from `useWingmanPoller` hook

### 2. Live transcript buffer = 120 seconds (full, no slice)

**Current state:** `knowledge-signal.ts` does `transcriptChunk.slice(-500)` — 500 characters was a budget decision, not quality-based.

**What it should be:** The full last **120 seconds** of raw transcript (word-for-word), no slicing. Original Phase 2 spec said 90s; raised to 120s this session to better handle long-winded prospects.

**Why not more than 120s:** The Belief Ladder scorecard already covers anything older than the live buffer (it updates every 2 minutes). The buffer's job is raw recency — the exact words just said. Beyond 120s you're duplicating what the scorecard already captured.

**Files to change in Phase 3:**
- `src/lib/wingman/knowledge-signal.ts` — remove `.slice(-500)`, accept full buffer
- Client-side hotkey handler — send last 120s of transcript at press time

### 3. Keep Haiku

Haiku stays for press-time signal cards. Sonnet (~600–1,500ms) is noticeably slower than Haiku (~200–400ms) and the speed matters on a live call. The quality gap right now is a context problem, not a model problem. Fix context + prompts first; revisit model only if cards still feel off after real calls with proper context.

No model toggle — unnecessary complexity.

Cost: ~$0.01. Not a bug. Leave it.
