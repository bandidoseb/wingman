- **Two new pure, unit-tested modules (32 new tests, 91 total):**
  - `src/lib/wingman/json-line-stream.ts` — incremental decoder that opens the `{"line":"…"}` envelope as it streams, emitting **only fully-resolved inner chars** (holds a dangling `\` or partial `\uXXXX`), stops at the unescaped closing quote, and classifies `null`/empty/whitespace as **abstain** — emitting **zero** deltas until a non-whitespace char resolves (so an abstain never flashes an empty card). Tested char-by-char for split escapes, split unicode, truncation, all abstain shapes.
  - `src/lib/wingman/sse-parse.ts` — pure SSE frame parser, used by BOTH the renderer's stream reader AND `streamObjectionCard` (to parse Anthropic's own SSE). Tested for split frames, split sentinels, CRLF, comment-only frames.

- **Server:** `streamObjectionCard()` (Anthropic `stream:true`) added to `objection-signal.ts`; `kb-signal/route.ts` objection branch returns an **SSE `Response`** (returned synchronously, Sonnet runs inside `start()`), headers `text/event-stream` + `Cache-Control: no-cache, no-transform` + `X-Accel-Buffering: no`, no Content-Length. Events: `delta` / `done` / `nudge` / `error`.

- **IPC + HUD:** new `hud:signal-delta` channel (preload invoke → main relay → HUD listener, mirroring `hud:signal`); HUD `handleSignalDelta()` feeds Step-3's reveal loop, seq-guarded; `openHeadlessShell()` extracted so the streamed card can't drift from the one-shot card.

- **Renderer:** `handleMenuPick` reads the SSE with `parseSSEBuffer`, branches on Content-Type (stream vs the untouched JSON fallback), monotonic `seq` per press, single idempotent `release()`, TTFB + idle-gap guards (not a flat wall), aborts the stream on dismiss + call-end (`!isActive`).

- **Compression proven empirically** (the reviewer's #1 risk): built a throwaway SSE route on a **real `next build && next start`** and curled it — **no `Content-Encoding: gzip`** (the `no-transform` header defeats Next's default gzip), `Transfer-Encoding: chunked`, chunks arrive incrementally. So no global `compress:false` needed. Throwaway route deleted. Railway runs the same `next start`; `X-Accel-Buffering: no` covers its edge.

- **wingman-reviewer: APPROVE** (0 blocking; 2 optional/theoretical notes). Web + electron `tsc` clean, 91/91 tests.

## Live-Test Bugs Found + Fixed (Session 3)

From Sebastian's two live runs (terminal logs):

1. **Cold first press self-aborted at ~6s → retry pill.** The server's `: ok` proxy-flush satisfied the client's time-to-first-**byte** clock and armed the 6s idle timer; Sonnet's cold first **token** (~6s, un-warmed) then tripped it. Fix: the idle timer arms only on a real **delta** (the flush yields no SSE event); TTFB clock clears on the first parsed event; widened margins (server TTFB 12s/total 20s, client TTFB 14s/idle 7s).
2. **`TypeError: Controller is already closed`** when the client disconnected mid-stream and the route tried to write an `error` frame into the closed pipe. Fix: a guarded `send()` helper — every enqueue is try/caught; a closed pipe returns false and breaks the loop (which stops Sonnet via the generator's finally).
3. **The real cure for slow cold presses:** the call-start warm-up pinged Haiku/Groq but **not Sonnet** (the objection model). Added a Sonnet 1-token warm ping → cold first press should drop from ~6s toward the warm ~2s. Confirmed by Sebastian ("first press is fast now").
4. **Rapid ↑↑↑ presses showed "couldn't pull that — retry" spam.** Root cause: no transcript (solo test) + the server's 3s cost guard dropping fast presses, which the client rendered as an *error*. Fix: a client-side **summon throttle** (3.5s, mirrors the server, silently ignores — no pill); the server rate-limit now returns a clean **429** + the client resolves the pill **quietly** via a new `idle` summon-state (edge backstop). Not a failure anymore.
5. **No-objection card dropped the "SUGGEST" tag** (Sebastian: reads wrong — it's an all-clear, not advice). `signalTag` hidden for `Nudge` type. NOTE: appeared "unchanged" in his test only because `electron:dev` compiles the HUD **at launch** — his running `electron-dist/hud` was stale (18:22 vs the 18:44 fix). A full restart loads it.

## Decisions Made and Why (Session 3)

| Decision | Reason |
|----------|--------|
| Prove compression on a real prod build, not just trust the research note | Sebastian explicitly wanted certainty it works on Railway/Next.js. The empirical curl settled it: `no-transform` defeats Next's gzip; no global change needed. |
| Idle timer arms on first DELTA, not first byte | The `: ok` flush is bytes-but-not-content; arming on it killed healthy cold streams during Sonnet's think-time. |
| Client throttle (3.5s) + server 429 quiet-resolve, instead of just patching the error copy | A too-fast press isn't a failure — silently ignoring it (like the in-flight guard) is the correct UX; the 429 is the edge backstop. Also matters for the multi-turn future (fast re-press). |
| Warm Sonnet at call start | The objection card is Sonnet; warming only Haiku left the first press cold (~6s). This is the actual latency cure, distinct from streaming (which masks think-time, not reduce it). |
