- **interim_results fix (commit 570fb17).** First measurement call returned **zero** partials. Root cause: Deepgram's `interim_results` defaults to `false`, so subscribing to the partial event alone yields nothing — we'd subscribed to the delivery channel but never turned on the tap. Added `interim_results: true` to the `deepgram_streaming` provider config in `recall-upload-token/route.ts`. Also added bounded per-call diagnostics in `recall.ts` (unknown event names logged once each, unparseable payloads max 5) so the log can never again silently read "no data."

- **#41 fix — live partial-tail merge at press time (commit e29be29).** The actual fix. `src/lib/wingman/live-tail.ts` (NEW, pure/tested) holds the freshest partial per speaker, swept on every update, cleared when that speaker's FINAL lands. At press time in `DashboardClient.handleMenuPick`: (1) **settle wait** — if a partial landed <1.5s ago the speaker is likely mid-utterance, so set `isGeneratingRef=true` + send the "thinking" pill, sleep 350ms, re-check `isActiveRef` (bail → idle pill + guard reset); (2) after the threading decision + capping, append a `[live — still being transcribed]`-marked line, deduped by **strict normalized substring**, then re-cap with `capLatest` (server rejects >3,500 chars; capLatest keeps the END so the live tail survives and only the oldest finals slice). `hotPartialAgeMs()` returns `+Infinity` when empty — the load-bearing guarantee that old packaged apps (no partial IPC) and post-pause presses get zero added latency + byte-identical requests. Wired through: `recall.ts` `onPartial` → `main.ts` `transcript:partial` IPC → `preload.ts` `onTranscriptPartial` (guarded, optional in types) → `useRecallTranscript` → `useWingmanPoller` (`addPartial`/`getLiveTail`/`hotPartialAgeMs`, ref reset in the `[callId]` effect). Prompt got a LIVE TAIL paragraph in `objection-prompt.mjs` teaching Sonnet to weigh the marked fragment as the latest words and judge completeness by meaning (not where the fragment stops), never echoing the marker.

- **Measured findings (2 real solo calls).** Finals lag live speech ~500ms median (p90 1–2.8s, max 4.1s); **Deepgram partials lag just 126ms.** Across presses, the finals-only pipeline missed 76 words and the partial stream already held 52 of them (**68% recoverable**); the rest is the last 1–2 words still in flight (settle-wait territory). Every live "no objection detected" abstain mapped to genuinely-missing prospect words — confirming the bug is transcript lag, not a prompt-judgment error.

## Decisions Made and Why

| Decision | Reason |
|----------|--------|
| Stay on Deepgram, don't switch to AssemblyAI | Measured Deepgram partials at 126ms median — faster than AssemblyAI's own claimed ~300ms. The bug was never the provider; it was that we ignored Deepgram's fast partial stream. A switch would delete the reconciliation layer but isn't needed. |
| Merge partials at press time rather than switch the whole live pipeline to partials | Finals stay the authoritative/durable record (DB saves, summarizer, anchors, cursors all finals-only); partials are ephemeral and ride only the outgoing request's volatile uncached segment. Keeps prompt-cache stability + never corrupts stored transcript. |
| 350ms settle wait, only when a partial is <1.5s old | Catches the last 1–2 words still streaming without adding latency to presses after a real pause. Invisible next to the ~2s generation. |
| Contextual abstains (build AFTER #41) | The generic "no objection detected" card wastes the most expensive silence on the call. Replace with a small enum of directive chips ("They're ready — close now.", "Let them finish.", etc.) as `{"line":null,"reason":<enum>}`. Build after #41 so the input is clean — otherwise it could flash "close now!" on half-arrived transcript. |
| The → close arrow = a PRE-PITCH readiness read, not a mid-action closing button | Sebastian's definition: it answers "am I clear to pitch?" before pitching — NOT "give me a closing line" mid-battle. Phase 4 must be built to this. Mid-objection "they're ready, close" is the abstain-chip's job, not the arrow's. |
