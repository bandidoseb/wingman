## 1. Live Hub core (electron/hud/index.html + WingmanMark.png)

the live indicator, with a hover→cog→settings panel. All in the one HUD file (+ one new logo asset).

- **Pill:** Wingman **logo mark** (cropped from `public/Wingman copy 2.png` → new `electron/hud/WingmanMark.png`
  — the bare mark, not the app-icon square), a **waveform**, bottom-left default, **draggable + position
  persists** (`hud-hub-pos`), inherits `setContentProtection` (invisible to prospect).
- **Post-Deploy confirmation:** shows **"Starting…"** (amber) on `deploy:state==='starting'` → **live**
  (green) on `call:started`; cancelled deploy clears it. Fixes the "flash then vanish" live-test gripe.
- **Retired the ambient dot safely** (kept the element/const, removed only its `.add('visible')` calls).
- **Fixed-height pill + smooth horizontal-only cog expand** (Sebastian: hover was "glitching" bigger) —
  cog animates width+margin, `height:34px` fixed → zero vertical jump.
- **Settings panel** (smooth fade-open, not display-toggle) with the **word-color customizer**: 4 presets
  (white/blue #7E9BFF/green #4ED188/yellow #F1D24C) + an **expanding canvas HSV color wheel** (white center →
  readable saturated rim; **no conic seams**, no native `<input type=color>` — that would show to the
  prospect). First `--signal-text` CSS token; recolors the live card instantly.
- **Waveform:** animates `transform: scaleY` (GPU-composited) — NOT height (which reflowed + looked glitchy);

**Design decisions locked this session (Sebastian):** no "Live" text on the pill · 4 wave bars (not 5) ·
logo mark not app icon · one consistent pill size, smooth L→R growth · rainbow selector in the swatch row,
same size, no caption · wheel expands to pick (not pixel-hunt on a 24px disc).

**Gates:** plan-reviewer hardened the plan first (3 ship-blockers designed out incl. the native-picker

## 2. Real listening waveform (5 files — Recall audio → pill bars)
The pill bars now react to REAL speech loudness (rep + prospect, mixed). Research first confirmed Recall's
Desktop SDK already streams `audio_mixed_raw.data` (base64 mono 16k S16LE PCM) over the channel we already
use — no extra Recall cost, no new mac permission.

- **`recall-upload-token/route.ts`** — OPT-IN: defensive `req.json()` parse (old apps send no body → no-op),
  conditionally subscribes `audio_mixed_raw.data` only when `{wantAudioLevel:true}`. Keeps every existing
  install byte-identical until the new app ships.
- **`recall.ts`** — `onAudioLevel` option; sends the opt-in flag on the token fetch; new `audio_mixed_raw.data`
  branch at the TOP of `realtimeHandler` (throttle ~25Hz → base64 decode → Int16 RMS → 0..1 clamp → emit,
  then return). **Audio NEVER stored** (Invariant #6): buffer RMS'd + discarded; one-time debug log prints
  KEYS only via `console.log` (never `logMeasurement`/bytes); returns above all disk-writing paths; doesn't
  touch `lastChunkAt`/dedup/`onChunk`.
- **`main.ts`** — wires `onAudioLevel` → `hudWindow.send('hud:audio-level', level)` with `isDestroyed()` guard.
- **`preload.ts`** — `onAudioLevel` on the hud bridge.
- **`index.html`** — `handleAudioLevel` + single rAF loop lerping bar `scaleY`, `.audio` class disables the CSS
  ambient anim (`!important`, after `.live`), ~1s fallback to ambient if audio stops, teardown in `hideHub`.

**Gates:** plan-reviewer hardened (opt-in flag, CSS-override trap, rAF lifecycle, NaN guard, PCM-to-disk audit).
wingman-reviewer = **APPROVE, no defects.** Typecheck clean (web+electron), 187 tests. **Live-tested good.**
Two live-verify items were fine: the base64 field path + PCM format (both fail safe to ambient if wrong).
