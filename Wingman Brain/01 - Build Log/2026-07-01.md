## What Got Built Today

- **🎉 macOS auto-updater FIXED end-to-end (Issue #45) — the marquee win.** Auto-update has never worked in the app's history; it does now, verified on Sebastian's Mac (0.1.25→0.1.26 auto-installed; 0.1.27→0.1.28 confirmed smooth self-relaunch). This took a **six-release gauntlet** (v0.1.23–v0.1.28) because each defect only surfaced by actually shipping:
  1. **Drafts** — electron-builder's GitHub publisher defaulted `releaseType: draft`; drafts are invisible to electron-updater. → `publish.releaseType: release`.
  2. **No `.zip`** — Squirrel.Mac (electron-updater's mac engine) can ONLY apply a `.zip`, never a `.dmg`; the build made only dmgs. → added a `zip` target (kept dmg for first manual download).
  3. **Notarization off** (`notarize: false`) despite all Apple secrets existing. → `notarize: true` (Developer ID cert confirmed correct; CI now notarizes — no more Gatekeeper warning, no more `xattr`).
  4. **Private repo → 404 (the real root cause).** Live test log showed `GET bandidoseb/wingman/releases.atom → 404`: a private repo has no public release feed, so the installed app can't see updates. → publish signed/notarized installers to a **separate PUBLIC repo `bandidoseb/wingman-releases`** (source stays private); electron-updater reads there. Auth via a fine-grained PAT `WINGMAN_RELEASES_TOKEN` (Contents:write on that repo only).
  5. **Empty-repo 422** — GitHub won't attach a release to a repo with zero commits; the new public repo was created empty. → seeded a README.
  6. **No auto-relaunch** — the main-window `close` handler *hides* unless `isQuitting` is set, so `quitAndInstall()` left the process alive (user had to force-quit 2–3×). → set **`isQuitting = true` before `quitAndInstall()`**.
  - Also hardened: dropped the x64/Intel target (Recall SDK is Apple-Silicon-only; the Intel dmg couldn't run and `latest-mac.yml`'s `path:` wrongly pointed at it); added `autoUpdater.on("error")` logging + `.catch()` on the update check (killed an unhandled-rejection crash path). Files: `electron-builder.yml`, `.github/workflows/release.yml`, `electron/main.ts`.

- **Stale-notes process fix (the session opener).** Root cause of the recurring "these notes are stale": `Current Sprint.md` hand-copies status that git/GitHub already owns, and that status moves after the wrap is written (e.g. streaming was written as "not pushed" then merged as PR #24). Principle: *prose holds decisions + intent; git holds status.*

## Decisions Made and Why

| Decision | Reason |
|----------|--------|
| Publish releases to a **public `wingman-releases` repo** (Option 1) | electron-updater needs a public release feed; the code repo is private (404). A separate binaries-only public repo keeps source private with least effort. Standard pattern for beta. |
| **Defer** self-hosted Railway update feed (Option 3) to scale | Big-company approach (control + gating), but real infra work; premature before beta. Captured in `_Inbox/Future Build - Self-Hosted Update Feed (Option 3).md`. Revisit with paying users / a dev. |
| Reject shipping a GitHub token inside the app to read the private repo | Violates Architectural Invariant #1 (no secrets in the binary). |
| Fine-grained PAT (Contents:write on wingman-releases only), no expiration | Least-privilege vs. the broad classic `repo,workflow` token; no-expiry is Sebastian's deliberate solo-founder tradeoff (dev will rotate later — noted in the Option 3 file). |
| Keep the stray private-repo releases (v0.1.22–0.1.24) | Zero risk to leave (inert, nothing reads the private feed); deleting is irreversible for the .dmg assets with no upside. |
