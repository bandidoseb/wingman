**In-call Prospect Anchor Capture** — Sebastian vision (2026-07-19 rant). Wingman should silently remember every heavy-hitting thing the prospect says across the whole call (their goal number, WHY that number, how long stuck, how close they got, final-straw moment, who burned them, what they've tried/spent) — the anchors an elite closer holds in working memory — and inject them into the live **dig (↓)** and **objection (↑)** cards. NOT needed on answer(←)/close(→).

**Why:** a great discovery is 30–60 min of probing; the closer is ALSO holding 10+ anchors AND deciding which to resurface mid-objection. That background cognitive load competes with being present. Wingman lifting it = the rep flows, stays present, digs better. Core differentiator vs. transcribe/coach-after tools.

**How to apply:** distinct from [[project-offer-aware-moat]] Sales DNA (offer-level, generic) and from cross-call Prospect Memory (`Call Continuity + Prospect Memory Design.md`). Anchors = THIS prospect, verbatim, this call. Plumbing is half-there: the **live call summary IS the Belief Ladder** (`calls.live_summary`, written by the ~2-min summarizer — same thing, not two layers), and it already injects into BOTH cards, so cleanest path = teach the **live summarizer** to also emit an "IMPORTANT PROSPECT CONTEXT / ANCHORS" section. Reverse-engineer the anchor taxonomy from the 7 beliefs (+ deadlines/stakes/repeated phrases); bar = "would a great closer remember this?". Same never-make-anything-up discipline.

**⚠️ CRITICAL (Sebastian 2026-07-19): the anchor instruction must be PER-REP, not hardcoded.** What counts as a significant anchor depends on what the rep sells — Desire is a revenue number for a biz-opp seller but a FEELING/image for a health/fitness seller. Do NOT instruct "find the number" generically. Parameterize the anchor instruction with the rep's **Sales DNA** (already loaded on the summarize tick as an interpretive lens): 7-belief scaffold = fixed categories; Sales DNA = what each category concretely looks like for THIS offer. So anchor capture is gated by a good Sales DNA, like the offer-aware cards.

Ties to [[project-summarizer-tuning-session]] (eval-gated summarizer change — a regression degrades every live card; cost matters since it runs every ~2 min every call). Objection card also needs Sales DNA added (the money-anchor "$30k months / land-flipping blueprint" specificity = task #4).
